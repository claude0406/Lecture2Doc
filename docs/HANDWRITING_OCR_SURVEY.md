# 손필기 OCR의 실사용 가능성

조사일: 2026-11-02. 논문 저자·모델 개발자·데이터 제공 기관의 공개 자료를 기준으로 정리했다.

## 판단

**문장 OCR은 C에 남길 가치가 있다.** 선명한 영문 손글씨는 텍스트 추출·검색용으로 시도할 근거가 충분하다. 한글과 촬영 판서는 별도 시험이 필요하다. 목표를 ‘판서 이미지에 붙는 텍스트’로 잡으면 일부 오자가 있어도 활용할 수 있다. 수식 전체를 정확한 LaTeX로 재작성하는 목표보다 적용 범위를 작게 시작할 수 있다.

추천 방향은 **C의 우선 구현을 문장 OCR로 좁히고, 수식→LaTeX는 후속 목표로 유지**하는 것이다. 아래 내용은 범위 조정 제안이다.

## 공개 수치를 어떻게 읽어야 하나

| 대상·모델 | 공개 결과 | 입력과 평가 조건 | 프로젝트에 주는 의미 |
|---|---:|---|---|
| TrOCR Small / Base / Large | CER **4.22 / 3.42 / 2.89%** | IAM 영문 손글씨, 대소문자 구분, 한 줄 인식 | 잘라낸 영문 손글씨의 현실적인 공개 기준선 |
| DAN | CER **4.54%**, WER **11.85%** | RIMES 프랑스어 손글씨 문서 한 페이지 | 문서 전체 인식도 가능하지만 글자 오류율보다 단어 오류율이 큼 |
| PP-OCRv6 medium | 영문 손글씨 **67.8%**, 인쇄 영문 **94.1%** | 개발자 내부 다중 환경 평가의 문자열 인식 정확도 | 범용 OCR에서도 손글씨는 별도 난점 |
| Korean PP-OCRv5 mobile | 줄 완전 일치 **88.0%** | 한국어 평가셋, 구두점 포함 한 글자라도 다르면 줄 오답 | 한국어 후보로 유용. 손글씨 하위 집합의 점수는 카드에 없음 |
| AI Hub 금융업 특화 문서 OCR | 손글씨 F1 **0.7219**, 인쇄글씨 **0.9667** | 문서의 검출·인식, 제공 기관의 Mask R-CNN 기반 모델 | 한국어 문서에서도 인쇄와 손글씨의 차이가 큼 |

출처: [TrOCR 공식 결과](https://github.com/microsoft/unilm/blob/master/trocr/README.md), [DAN 공식 결과](https://github.com/FactoDeepLearning/DAN/blob/main/README.md), [PP-OCRv6](https://www.paddleocr.ai/latest/en/version3.x/algorithm/PP-OCRv6/PP-OCRv6.html), [한국어 모델 카드](https://huggingface.co/PaddlePaddle/korean_PP-OCRv5_mobile_rec), [AI Hub 데이터·평가](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=632).

**CER은 `(치환+삭제+삽입)/정답 글자 수`다.** CER 2.89%는 정답 1,000자당 편집 오류 약 29건에 해당한다. 문장 100개 중 97개가 완벽하다는 뜻은 아니다. WER은 단어 단위 편집 오류율이고, 줄 완전 일치는 한 줄 전체가 맞은 비율이다. 서로 다른 지표와 데이터셋의 수치를 하나의 정확도 순위로 합치지 않는다.

앞서 수식에서 본 ExpRate는 **식 전체가 맞은 비율**이다. OCR의 낮은 CER과 수식의 전체 정답률을 비교해서 ‘OCR은 97%, 수식은 70%’라고 읽으면 조건이 달라진다. 기존 A/B F1 역시 판서 픽셀 평가이며 OCR 글자 정확도와 별개다.

## 종이 손글씨와 강의 판서의 차이

TrOCR의 공개 handwritten 체크포인트는 IAM으로 미세조정한 **한 줄 인식기**다. 전체 칠판에서 줄을 찾아주는 기능은 별도로 필요하다. [모델 설명](https://huggingface.co/microsoft/trocr-base-handwritten).

판서에는 글자 인식 전에 해결할 문제가 있다.

- 줄 검출: 문장 옆의 그래프·화살표·수식 때문에 줄을 놓치거나 잘못 자를 수 있다.
- 영상 품질: 멀리 있는 작은 글자, 압축, 희미한 펜, 반사광, 인물과 복원 경계가 입력에 남는다.
- 표기 혼합: 영어 설명 안의 `L₁`, `x+y`, 지수와 기호는 일반 문장과 다르게 읽힐 수 있다.
- 읽기 순서: 좌우 두 단과 중간에 추가한 주석을 올바르게 연결해야 한다.

촬영 손글씨 자료인 [GoodNotes GNHK](https://github.com/GoodNotes/GNHK-dataset)도 후속 비교 자료로 적합하다. Intel의 GNHK용 소형 인식기는 82.0% accuracy를 공개한다. 해당 문서는 label error rate 기반 지표를 사용하며, GT 좌표로 한 줄을 자르고 적응 이진화한 입력 및 너비 제한을 명시한다. 이 값은 줄 완전 일치율로 해석하지 않는다. [Intel 모델·전처리 조건](https://github.com/openvinotoolkit/open_model_zoo/blob/master/models/intel/handwritten-english-recognition-0001/README.md).

따라서 종이·문서 벤치마크는 후보 선정 근거로 쓰고, 채택 여부는 A/B의 실제 판서에서 판단한다. 이 프로젝트에서는 원본 해상도 이미지와 위치·출처가 이미 있으므로 인식 결과를 해당 영역에 연결할 수 있다.

## 한글은 어떻게 볼 것인가

한글은 별도 한국어 체크포인트로 시험한다. 영문 TrOCR의 IAM 점수를 한국어 예상 성능으로 쓰지 않는다. 한국어 v5의 88%도 한국어 판서나 흘림 손글씨만의 점수로 확대하지 않는다.

상용 경로도 있다. NAVER는 한국어·손글씨 OCR 기술을 HyperCLOVA X Vision에 활용한다고 설명한다. 다만 해당 소개의 일반 문서 이해 점수를 한글 손글씨의 CER로 바꿀 수는 없다. [NAVER 공식 기술 소개](https://clova.ai/en/tech-blog/en-introducing-hyperclova-x-vision).

현재 AccessMath 입력은 영어 중심이다. 한글 채택 판단에는 실제 한글 판서 표본을 추가하고, NFC 음절 기준 CER과 공백 포함·제외 점수를 함께 남기는 것이 좋다. 자모 단위 점수는 별도 항목으로 표시한다.

## OCR 전용 엔진과 이미지 입력 LLM

| 경로 | 역할 | 우선 확인할 점 |
|---|---|---|
| 로컬 OCR | 줄 검출 + 글자 추출, 영역 좌표 저장 | 실제 판서 CER, 줄 누락, CPU 처리 시간 |
| OpenAI 등 이미지 입력 VLM | 판서 crop 자체를 보고 문장·혼합 표기 전사 | OCR보다 실제 오류가 줄어드는지, 생략·추가·문구 변경, 호출 비용 |
| OCR 텍스트를 LLM에 전달 | 이미 읽은 텍스트의 문맥 보정 | 원래 보이던 획을 다시 볼 수 없으므로 원본 인식과 분리 저장 |

OpenAI Responses API는 이미지 입력과 텍스트 출력을 지원한다. 판서 전체를 작게 보내기보다 원본 해상도의 문장/블록 crop을 보내는 비교가 적합하다. 공식 이미지 가이드도 작은 글자의 확대와 비라틴 문자 인식 특성을 설명한다. API의 한국어·손필기 성능은 같은 crop에서 측정한다. [OpenAI 이미지 입력 가이드](https://developers.openai.com/api/docs/guides/images-vision).

**추천은 엔진을 교체할 수 있게 만드는 것**이다. 로컬 OCR을 첫 기준선으로 두고, API 방식도 같은 입력·출력으로 비교한다. API가 실제 판서에서 크게 앞서면 기본 엔진으로 선택할 수 있다. 전용 OCR보다 항상 더 정확하다는 전제는 두지 않는다. 모델의 confidence만으로 API 재시도 대상을 정하기보다, 줄 누락·엔진 간 불일치도 함께 살펴본다.

원시 전사와 이후 교정 결과를 분리하고 입력 crop·좌표·원본 프레임을 연결한다. 이 방식이면 OCR/API를 바꿔도 A/B 결과와 복원 근거를 그대로 활용할 수 있다.

## 다음 실험을 작게 시작하는 방법

1. 실제 A/B 판서에서 **영문 60줄**, 한글 판서가 준비되면 **한글 60줄**을 만든다. 선명/희미함/기울기/수식 혼합 표본을 포함하고 사람이 전사 정답을 작성한다.
2. 동일 crop으로 **PP-OCRv6 medium ↔ TrOCR Base**를 비교한다. 한국어는 별도 v5 모델을 사용한다. 이어 같은 crop에 이미지 입력 API를 비교한다.
3. CER·WER·줄 완전 일치와 오류 예시를 기록한다. 모델별 초/줄·메모리, API는 토큰·비용을 함께 남긴다. 전처리는 RGB와 이진화를 비교한다.
4. 후보가 좁혀지면 자동 줄 검출까지 포함해 **놓친 줄 수·글자 크기별 오류**를 평가한다. 시험 강의는 개발에 사용한 01/02/06과 분리한다.

프로젝트용 초기 목표를 정한다면, **본문 CER 5% 이하와 줄 검출 재현율 95% 이상**을 출발점으로 제안한다. 이는 검색·복사 초안을 위한 개발 목표다. 실제 검색 기능은 D에서 구현하며, 그때 키워드 검색 성공률을 별도로 확인한다. 전문용어·제목 오류도 함께 보아 채택을 결정한다.

수식과 행렬은 이미지를 보존하고, LaTeX 추출은 별도 후속 실험으로 둔다. C의 문장 OCR 진척이 수식 인식에 막히지 않는 구성이 적합하다.

## 이번 조사 반영

공개 결과·적용 조건·엔진 후보·후속 평가안을 정리했다. 다음 단계는 실제 판서 crop의 전사 정답과 인식 결과를 만드는 것이다. 기존 A/B 실행 결과와 수식 서베이 자료는 유지한다.
