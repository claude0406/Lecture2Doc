후속 작업으로 누적 판서 B를 구현했다. 현재 동작과 실제 검증 한계는 [B 복원 보고서](PAGE_RESTORATION.md)를 참고한다. 아래 내용은 A 구현 당시의 실험 기록이다.

A의 출력 단위를 수정했다. **영상당 한 장이 아니라, 필기 누적 후 삭제·교체되는 각 판서마다 대표 원본 한 장**이다. 필기 추가와 사람 이동으로 생기는 중간 상태는 내부 진단 및 원본 관측으로 보존한다. B로 여러 시점의 픽셀을 합치는 작업은 이번 변경에 포함하지 않았다.

새 누적 판서 B는 **미구현**이다. 비교 HTML의 `page_B_original_fallback`은 A와 동일한 원본을 사용한 대체 출력으로, B 알고리즘의 성능이나 개선 증거가 아니다. 기존 중간 상태 B는 보존하되 누적 판서 B로 표시하지 않는다. 웹 업로드와 CLI는 기본적으로 A를 실행하고, CLI `--reconstruct`는 진단용 기존 중간 상태 B를 추가 계산한다.

평가에는 기존 `accessmath_evaluate.py`의 `annotations`, `predicted_ink`, `score`를 그대로 불러왔다. 이진화 threshold 10/20/30, 3px 허용 거리, 공식 비내용 영역 제외, R/P/F1 계산은 변경하지 않았다. 위 표는 threshold 10의 GT별 macro 평균이다. 새 출력은 **GT 시점이 속한 누적 판서**로 평가한다. 따라서 GT 스냅샷 이후에 추가·수정된 내용도 대표에 포함될 수 있다. 점수 계산은 비교 가능하지만 출력의 시간적 의미가 달라졌으며, 공식 unique-CC 요약 점수는 아니다. GT·GT 시각·공식 구간은 알고리즘 입력에 들어가지 않는다.

## 원인과 수정

기존 `vision.analyze()`는 확인된 추가·삭제 픽셀이 임계값을 넘을 때마다 상태를 닫았다. 이 상태를 웹 목록에 그대로 표시해 필기 중간 단계가 각각 최종 판서가 됐다. 전체 구간의 빈도 기반 대표 선정은 늦게 추가된 필기와 최종 완성도를 직접 반영하지 못했다.

`lecture2doc/pages.py`에 기존 관측·가림 추정 위에서 동작하는 누적 판서 단계를 추가했다. 기존 분석·복원과 원본 디코드 계약은 유지했다.

- 필기 추가는 누적한다. 기본 0.5초 샘플링에서 가림 없는 필기 관측 6회로 확인하며, 가려진 동안의 확인 기록은 유지한다. 가림을 삭제 증거로 사용하지 않는다.
- 보였던 글자가 가림 없이 2초 상당 연속 사라지는지 확인한다. 4초 창에서 사라진 고유 픽셀이 60개 또는 누적 필기의 8% 이상이면 삭제·수정을 검토한다. 작은 소실을 수십 초 동안 무한히 합산하지 않는다.
- 삭제 시작 전 참조를 고정해 삭제 후에 새로 작성된 글자가 이전 판서 목표에 섞이지 않도록 한다. 지우는 도중 추가 내용이 거의 없고 깨끗한 원본도 없는 부분 상태는 지우기 과정으로 흡수하고 그 판단을 이벤트 JSON에 남긴다.
- 원본에서 반복 관측되는 맞은편 긴 테두리 쌍이 있을 때만 분석용 칠판 경계를 추정한다. 고정 전경·테두리를 필기량에서 제외한다. 반복적으로 가려진 큰 영역은 완전성 미확인 경고를 남긴다. 출력 원본을 자르거나 배경을 생성하지 않는다.
- 검증된 작은 카메라 이동은 기존 배경 특징점 변환으로 **분석 마스크만 정렬**한다. 확인되지 않은 위상 이동값만으로 페이지를 나누지 않는다. 큰 이동·컷은 대응 관계를 끊는다.
- 대표 후보는 삭제 직전 확인된 필기의 실제 노출률, 가림, 다른 필기, 선명도를 비교한다. 점수는 `노출률 − 0.6×추가 필기 비율 − 0.15×가린 필기 비율 − 0.03×전경 비율 + 최대 0.002의 선명도 보너스`다. 검출 픽셀 수를 그대로 최대화하지 않는다. 상위 8개 대안과 모든 후보의 점수를 보존한다.
- 안정된 관측이 부족한 짧은 영상도 원본 후보와 불확실성 표시를 남긴다. A 결과는 원본 프레임 경로만 참조하며 새 판서 RGB 픽셀을 만들지 않는다.

관측 특징은 128프레임씩 별도 캐시에 원자적으로 저장한다. 페이지 정책을 다시 실행해도 디코드와 특징 측정을 반복할 필요가 없다. 새로운 `board_pages`가 기본 출력이며, 기존 `board_states`는 중간 상태 진단용 필드다. 오래된 기록에는 이전 형식 안내를 표시한다.

## 607초 사례

공식 GT 시각은 평가 및 이 사후 진단에만 사용했다. 해당 판서는 371.872–654.154초로 누적된다.

| 원본 | 말기 필기 노출 추정 | 필기 가림 추정 | 선정 점수 |
|---|---:|---:|---:|
| 깨끗한 607.607초 | 99.64% | 0.25% | 0.9952 |
| 기존 선택 616.1155초 | 74.84% | 25.08% | 0.7085 |

607.607초 원본도 상위 품질 후보로 평가된다. 최종 선정은 GT에 더 가까운지를 보지 않고 해당 판서의 말기 필기 노출을 비교해 644.644초를 고른다. 해당 GT의 F1은 기존 **73.27% → 96.32%**이고, 730.530초 사례도 **79.33% → 96.84%**다. 후보별 진단은 `607-case.json`, 비교 이미지는 `607-case.jpg`에 있다. 노출 추정은 모델 없는 마스크 기준이므로 실제 읽기 품질의 정답 비율로 해석하면 안 된다.

**완료된 것은 A의 출력 단위·대표 원본 선정의 1차 개선이며, 모든 영상에서 정확한 분할이 보장되는 단계는 아니다.** testing 초반 제목만 있는 구간과 비슷한 제목 장면이 별도 판서로 남는 과분할이 있다. testing 441.708초 GT는 대표 512.012초와 내용이 달라 F1이 **99.96% → 96.73%**로 낮아진다. 작은 작성·수정의 상태 경계를 충분히 구분하지 못한 사례로 남겼다. 내용을 추가하면서 최종본을 기록하는 목표와 GT 시점별 스냅샷 평가의 차이도 함께 고려해야 하며, 점수를 유리하게 만드는 GT 기반 대표 선택은 하지 않았다.

3초 상당 관측을 확보하기 전에 추가·삭제되는 필기, 작은 수정, 긴 가림, 배경과 비슷한 색의 사람, 조명 변화, 테두리와 유사한 그림, 여러 칠판을 오가는 카메라는 남은 위험이다. 지우는 과정으로 흡수하는 규칙이 중요한 중간 판서를 합칠 수도 있다. 흡수 이벤트와 원본을 남겨 검토할 수 있게 했다. testing 분할도 개발 중 검증에 사용했으므로 최종 독립 blind 검증이라고 주장하지 않는다.

다음 B 작업은 이 누적 판서 구간 안에서 실제로 필요한 부분만 합치고, 다른 판서의 픽셀을 섞지 않으며, 원본보다 나은지 확인하는 것이다. 실제 가림 복원 개선은 이번 A 실험으로 입증하지 않았다. C의 OCR·LaTeX·노트는 별도 미구현 단계다.

## 검증과 재현

**최종 자동 테스트 31개 통과.** 전체 자동 테스트 결과는 `experiments/board-pages/tests-final.txt`에 있다. 추가 테스트는 필기 추가 누적, 한 영상의 여러 완성 판서, 부분 삭제, 가림과 삭제 구분, 지우기 과정, 작은 카메라 이동, 교대 가림, 짧은 영상의 원본 유지 및 실제 MP4 → 파이프라인 연결을 확인한다. 합성 관측 8종의 결과는 `synthetic-observations.txt`로 실제 AccessMath 평가와 분리했다. 그 스크립트의 컷 사례는 카메라/컷 메타데이터 없이 페이지 단계만 단독 실행한 결과이며, 전체 파이프라인의 컷 검증은 자동 테스트가 담당한다. 테스트 통과를 실제 판서 품질 개선 근거로 대신하지 않았다.
